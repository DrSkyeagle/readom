# 文档

按"你是谁、你想知道什么"排的。这个索引里列出的每一份都有中英文两版
（`*.en.md`），结构由 `tools/tests/test_doc_pairs.py` 钉住。

## 想把它装到 Kindle 上

| 文档 | 回答什么 |
|---|---|
| `../README.md` | 这是什么、支持哪些机型、现在能用到什么程度 |
| `install.md` | 怎么装、装之前要准备什么、出错了看哪里 |
| `known-issues.md` | 知道、查过、**决定不改**的问题，以及查实无害的日志噪声 |

## 想知道还差什么

| 文档 | 回答什么 |
|---|---|
| `open-items.md` | 还没做完的事：开头是已知故障，然后是改好了等上机确认的、还没走过的验证、设计好但没做的，各自卡在哪 |
| `../CHANGELOG.md` | 每一版改了什么、在设备上验到哪里；官网的更新日志和 GitHub Release 的说明都从它来 |

## 想改代码

| 文档 | 回答什么 |
|---|---|
| `../CONTRIBUTING.md` | 构建环境、测试、补丁系列的只追加规则、框架资源的两条规矩、提交约定 |
| `../SECURITY.md` | 不写分区的保证、设备专属数据、隐私检查、签名密钥 |
| `../THIRD_PARTY.md` | 用了谁的代码、各自什么许可、改没改过 |
| `../CODE_OF_CONDUCT.md` | 参与这个项目的行为准则，以及怎么反映问题 |
| `design/README.md` | 设计记录的索引 |

**先落到哪个目录**：五个目录各有一份 README，讲这一块是什么、从哪儿读起、有哪两件容易踩的
——`../boot/`（启动链）、`../device/`（设备树）、`../installer/`（设备端安装器）、
`../patches/`（AOSP 与内核补丁）、`../tools/`（构建与检查脚本）。这几份只有中文。
`../config/` 没有：那里五个文件各自开头就写着自己是什么、谁读它，再加一层索引是多的。
